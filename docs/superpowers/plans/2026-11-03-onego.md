# onego Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A reusable skill plus bundled Node CLI that runs several independent actions (PROS sends, USDC sends,
Prosper buys) in ONE Pharos mainnet transaction from a plain wallet, without giving anyone rights to it, and
reports per-action results and the comparison with one-by-one transactions.

**Architecture:** The agent turns plain words into a plan JSON. `onego check` resolves and simulates the whole
Multicall3 `aggregate3Value` batch with state overrides (no key needed), `onego send` re-simulates, signs and sends
it with the user's key from `.env`, then verifies on chain. Chain access goes through one `Chain` interface that
can be recorded to tapes and replayed offline in tests (same idea as 14-whatswrong's witness).

**Tech Stack:** TypeScript (NodeNext, ES2022, strict), viem 2.57.7, node:test, esbuild 0.28.2 bundle into
`skill/onego/scripts/onego.mjs`. Same versions as 14-whatswrong.

**Spec:** `docs/superpowers/specs/2026-11-03-onego-design.md`

## Global Constraints

- Folder `15-onego`, standalone package like `14-whatswrong` (own package.json, tsconfig extends `../tsconfig.base.json`, not in root workspaces). Installs only on drive D.
- Chain id 1672, RPC `https://rpc.pharos.xyz`; on error code `-32011` (or HTTP 429) wait 1.5 s and retry, up to 8 times.
- Never `approve`, never `permit` to a middleman, never EIP-7702. Only Multicall3 `0xcA11bde05977b3631167028862bE2a173976CA11`.
- PROS-carrying calls `allowFailure = false`; USDC `transferWithAuthorization` calls `allowFailure = true`; read-backs `allowFailure = true`.
- USDC `0xC879C018dB60520F4355C26eD1a6D572cdAC1815`, 6 decimals, EIP-712 domain `{name: "USDC", version: "2", chainId: 1672}`, balance mapping slot 9. WPROS `0x52C48d4213107b20bC583832b0d951FB9CA8F0B0`, balance mapping slot 3. Prosper V2 factory `0x9343d6f1a7058a9ffd43028666db23cfce3e0d1e`, pair fee 0.5%: `out = in*9950*rOut / (rIn*10000 + in*9950)`.
- Never use the Prosper router `buyInnerNative` (pays Multicall3). Curve buys: `market.buyNative(minOut, deadline, recipient)` selector `0x383f5607`, `value = quoteBuy(amount).usedGross`.
- Authorizations valid 15 minutes. Refuse to send if simulation shows any action failing or Multicall3 holding anything (tokens, WPROS, PROS) after the batch. Never split a batch; refuse above a gas cap of 30,000,000.
- The key only in `.env` in the data folder (`PRIVATE_KEY=0x...`); never printed, never accepted on the command line. `check`, `recipients` need no key.
- Code, comments, docs, UI text in English, no em dashes. Non-generic names, conversational comments (as in 14). Commits as vi11abajo, human-sounding messages, no co-author, commit AND push after every task.

## Review Focus

- Rate limit mid-simulation (`-32011`): must retry, never be reported as an action failure. Test in Task 1.
- A plan with the same recipient twice, the wallet itself, or a contract address as an airdrop target: dedupe in `recipients`, refuse duplicates and self in `parsePlan`. Tests in Tasks 2 and 4.
- Amounts with more decimals than the token has (`0.0000001` USDC) or zero/negative: rejected, never rounded to 0. Test in Task 2.
- Wallet short of PROS for buys + gas, or short of USDC: `check` says so per action in plain words (the simulation mirrors real balances). Test in Task 6.
- Price moved between `check` and `send`: `send` re-simulates and sends nothing if anything fails now. Test in Task 8.
