# kickback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A SkillEngine skill `kickback` whose one command `draw` collects the last N real buyers of Prosper tokens through Chain MCP, commits the list on chain, picks K winners from the hash of a future block and pays them, plus `verify` that re-derives the winners from the commit tx alone.

**Architecture:** TypeScript in `17-kickback/src`, built with tsc and bundled by esbuild into `skill/kickback/scripts/kickback.mjs`. Every chain read and write goes through a `Chain` interface backed by the hosted Chain MCP (`mcp.pharos.xyz`); tests back it with recorded tapes or an in-memory fake. Signing is local with viem; broadcasting is Chain MCP `send_raw_transaction`.

**Tech Stack:** Node 20+, TypeScript 5.9.3, viem 2.57.7, @modelcontextprotocol/sdk 1.32.1, esbuild 0.28.2, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-04-kickback-design.md`

- No em dashes anywhere (code, comments, CLI strings, docs). English only in the repo. Names with some character, comments in a human conversational voice (tasks 14-16 style).
- Pacific Mainnet only: chainId 1672. USDC `0xc879c018db60520f4355c26ed1a6d572cdac1815` (6 decimals), WPROS `0x52c48d4213107b20bc583832b0d951fb9ca8f0b0`, Prosper V2 factory `0x9343d6f1a7058a9ffd43028666db23cfce3e0d1e`.
- Swap topic `0xd78ad95fa46c994b6551d0da85fc275fe613ce37657fb8d5e3d130840159d822`, Transfer topic `0xddf252ad1be2c89b69c2b068fc378daa952ba7f163c4a11628f55a4df523b3ef`.
- Chain MCP URL `https://mcp.pharos.xyz/mcp` (override `PHAROS_MCP_URL`), one session per run, paced at 115 calls/min, get_logs windows of at most 1000 blocks. MCP `eth_call` args are `{ transaction: {to, data, ...}, block? }`.
- Key only from `KICKBACK_HOME/.env` (`PRIVATE_KEY=`); never printed, logged, or taken from the command line.
- Defaults: pool 30 (2..100), winners 3 (1..10, < pool), amount 0.00001, token USDC (USDC|PROS), delay 5 (1..50), look-back 50,000 blocks. Caps in `config.json`: `max_total_usdc` "0.0001", `max_total_pros` "0.001".
- Commit data prefix ASCII `kickback:1:`; PROS token encoded as the zero address.
- Claude never runs `draw` without `--dry` during the build. Live draws are launched by the user.
- Git: commit and push to `main` as the user, short human commit messages, no co-author trailers. Commit after each task.

## Review Focus

- Fewer buyers than `pool` inside the look-back: draw from those found if at least 2 and say so; fewer than 2 stops before any commit. (Task 3 test `collectPool stops at the look-back cap`, Task 5 test `draw refuses with fewer than 2 buyers`.)
- A crash after the commit or between payouts: `--resume` must never pay a winner twice; a payout already signed is re-broadcast from its stored raw tx, not re-signed. (Task 5 test `resume never pays twice`.)
- Not enough USDC or PROS for winners x amount plus worst gas: stop before the commit, nothing signed. (Task 5 test `draw stops before commit when broke`.)
- Block N not yet visible on the load-balanced node (`get_block` null or "block is not available"): keep waiting, do not fail. (Task 5 test `waits through a missing target block`.)
- An amount below one raw unit (0.0000001 USDC) or a request over the cap: rejected with the reason before any chain write. (Task 2 tests.)

### Task 4: The commit and the draw

**Files:**

**Interfaces:**
- Produces in `commit.ts`:
  - `type Commit = { snapshot: bigint; delay: number; winners: number; token: Address; amountRaw: bigint; pool: Address[] }` (token = USDC address or `0x000...0` for PROS)
  - `encodeCommit(c: Commit): Hex` = hex of ASCII `kickback:1:` concatenated with `encodeAbiParameters` of `(uint64,uint16,uint16,address,uint256,address[])`
  - `decodeCommit(data: Hex): Commit` (throws `not a kickback commit` when the prefix is missing)

### Task 5: The draw flow, payouts and resume

**Files:**
- Create: `17-kickback/src/flow.ts`, `src/flow.test.ts`, `src/pay.ts`, `src/pay.test.ts`, `src/fakechain.ts` (in-memory chain for tests: balances, nonces, blocks advancing on each `blockNumber` call, receipts with Transfer logs, a switch to make a payout revert or a block go missing once)

**Interfaces:**
- Consumes: everything above.
- Produces in `flow.ts`:
  - `type Payout = { winner: Address; raw?: Hex; tx?: Hex; status: "pending" | "sent" | "paid" | "failed"; error?: string }`
  - `type DrawState = { version: 1; params: DrawParams; wallet: Address; pool: Pool; commit?: { raw: Hex; tx: Hex; block?: bigint }; target?: { block: bigint; hash?: Hex }; seed?: Hex; payouts: Payout[]; calls: CallLog[]; startedAt: string; finishedAt?: string }`
  - `runDraw(deps: { chain: Chain; account: PrivateKeyAccount; caps: Caps; home: string; say: (line: string) => void }, params: DrawParams, opts: { dry: boolean }): Promise<DrawState>`
  - `resumeDraw(deps, commitTx: Hex): Promise<DrawState>`
- Produces in `pay.ts`:
  - `signTx(chain, account, tx: { to: Address; data?: Hex; value?: bigint }): Promise<{ raw: Hex; hash: Hex }>` (nonce from `get_transaction_count`, gas = estimate x 1.2, legacy gas price from `get_gas_price`, chainId 1672)
  - `broadcastAndWait(chain, raw: Hex, hash: Hex): Promise<Receipt>` (send_raw; if the error says "already known" or the hash is on chain, carry on; poll `receipt` every 1 s, up to 120 s)
  - `paidRight(r: Receipt, p: { token: Token; from: Address; to: Address; amountRaw: bigint }, tx: TxInfo): boolean` (USDC: success + a USDC Transfer log from/to/amount; PROS: success + `tx.to`, `tx.value`)

Order inside `runDraw` (each block opens with `chain.step(name)`, `say` prints one plain line per step; no fixed phrases beyond labels):
`params` checkParams -> `snapshot` blockNumber -> `pool` collectPool (stop if < 2 people) -> `budget` balance + USDC `balanceOf` (0x70a08231) vs winners x amount and worst gas (estimate x price for commit and each payout) -> if dry: return state without signing -> `commit` signTx self tx with `encodeCommit`, save state BEFORE broadcasting, broadcastAndWait -> `target` N = commit block + delay, poll blockNumber every 1 s until >= N, `block(N)` until it has a hash -> `draw` seedOf + pickWinners -> `payout` per winner: signTx (USDC `transfer` or PROS value), store raw + hash + status "sent" and save BEFORE broadcasting, broadcastAndWait, `paidRight` -> "paid"; a payout whose estimate reverts twice -> "failed" with the reason, continue with the next -> `done` appendHistory, save.

`resumeDraw`: load state; commit without block -> broadcastAndWait(stored raw); missing target -> wait as above; missing seed -> draw; each payout "sent" -> broadcastAndWait(stored raw) (never re-sign); "pending" -> as in runDraw; "paid"/"failed" untouched.

### Task 6: verify

**Files:**
- Create: `17-kickback/src/verify.ts`, `src/verify.test.ts`

**Interfaces:**
- Produces: `type Verdict = { match: boolean; commit: Commit; commitBlock: bigint; target: { block: bigint; hash: Hex }; winners: Address[]; payouts: { winner: Address; tx?: Hex; ok: boolean; note: string }[]; firstDifference?: string }`
- `verifyDraw(chain: Chain, commitTx: Hex, payoutTxs: Hex[]): Promise<Verdict>`: `get_transaction` (must be a self tx: from = to), decode data, receipt block C, `block(C + delay)` hash, `seedOf` + `pickWinners`. PROS payouts: each given tx via `transaction` + `receipt`, matched to a winner by `to` and `value`. `match` = every winner has a correct payout; a missing payout is a difference, a winner whose payout is absent gets note "no payout found".
